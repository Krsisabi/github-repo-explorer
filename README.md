# GitHub Repo Explorer

Поиск по репозиториям GitHub через GraphQL API: список с курсорной пагинацией на главной и карточка репозитория с деталями.

Демо: **https://github-repo-explorer-app.vercel.app**

## Стек

React, TypeScript, Redux Toolkit, RTK Query поверх `graphql-request`, типы генерируются из схемы GitHub через `graphql-codegen` (client-preset), сборка на Vite, стили на SCSS-модулях без UI-библиотек, e2e на Cypress.

## Как устроен доступ к API

GitHub GraphQL API требует токен на любой запрос, включая публичные данные. Токен нельзя держать во фронтенде: всё, что попадает в клиентский бандл, публично по определению, и утёкший токен GitHub отзывает.

Поэтому запросы идут через serverless-функцию `api/github.ts`. Токен живёт в переменных окружения на сервере, клиент ходит на `/api/github` и не видит никаких учётных данных.

Прокси не пересылает в GitHub то, что пришло из браузера. Тексты трёх запросов приложения лежат на сервере (`api/operations.ts`), и клиент выбирает из них по имени операции — сам документ, если он пришёл, читается только ради этого имени и отбрасывается. Иначе прокси был бы открытым ретранслятором: имя операции пишет тот, кто отправляет запрос, поэтому проверка имён пропускает любой чужой запрос, названный «правильно». Переменные проверяются отдельно, размер страницы ограничен сверху — часовой лимит токена общий для всех, кто открыл демо.

Схема GitHub и сгенерированные из неё типы намеренно не в репозитории: это производные артефакты, которые восстанавливаются командой `npm run prepare:types` — её же выполняют CI и сборка на деплое.

## Как устроена пагинация

В GraphQL у GitHub нет номеров страниц. `search` — курсорное соединение: попросить можно только «столько-то штук после вот этого курсора», а сам курсор приходит в ответе на предыдущий запрос. Попасть в окно N можно лишь запросив окно N−1 и прочитав его `endCursor`.

Приложение тянет **окно в 100 результатов** и режет его на страницы по 10 на клиенте. Внутри окна перелистывание не стоит ни одного запроса; на границе уходит ровно один — за следующим окном. Пройденные курсоры запоминаются, а окна лежат в кеше RTK Query, поэтому назад листается бесплатно.

Номера страниц при этом честные, а не «сколько успели загрузить». `repositoryCount` даёт число совпадений, но наружу `search` отдаёт **не больше 1000 результатов** независимо от него — проверено по живому API: после `cursor:990` приходит `hasNextPage: false` и пустая выдача. Отсюда последняя достижимая страница — `ceil(min(количество, 1000) / 10)`, и интерфейс прямо пишет, что глубже поиск GitHub не пускает. Номер страницы живёт в адресе; выход за диапазон исправляется в самом адресе, чтобы перезагрузка не повторяла путь в никуда.

Одна деталь про цену запроса. В списке берётся скалярное `pushedAt`, а не обход `defaultBranchRef → target → committedDate`. Оба отвечают на вопрос «когда это трогали», но обход резолвит коммит для **каждого** репозитория: на сотне результатов это добавляло около 3.7 секунды (8.7 против 5.0 по замеру), из-за чего поиск не укладывался в срок ожидания прокси и возвращал 502.

## Запуск

```bash
npm install
npm run prepare:types   # скачать схему GitHub и сгенерировать типы
```

Дальше есть два режима, и разница между ними важна.

**`npm run dev` — только интерфейс.** Поднимает Vite на `localhost:5173`. Серверную функцию он **не запускает**: папка `api/` — соглашение хостинга, а не сборщика, и Vite про неё ничего не знает. Запросы на `/api/…` он просто пересылает на `localhost:3000` (см. `vite.config.ts`). Если там никто не слушает, страница откроется, а данных не будет — без ошибки на экране. Годится, когда правишь вёрстку и не трогаешь `api/`.

**`vercel dev` — интерфейс и функция.** Эмулирует хостинг целиком: поднимает фронтенд, превращает файлы из `api/` в настоящие обработчики и выдаёт им переменные окружения.

```bash
vercel link            # один раз, привязать папку к проекту
vercel env pull .env.local   # вытянуть GITHUB_TOKEN из настроек проекта
vercel dev             # фронтенд + функция
```

Токен вводить руками не нужно — `vercel env pull` берёт его из настроек проекта, а `.env.local` закрыт `.gitignore`. Если поднимаете свой экземпляр, токену достаточно прав на чтение публичных данных (fine-grained, `Public repositories → read-only`).

Правило переписывания в `vercel.json` исключает не только `api/`, но и адреса, которые дев-сервер Vite обслуживает сам (`/@…`, `/src/…`, `/assets/…`, `/node_modules/…`). Без этих исключений `vercel dev` отвечает на запрос `/src/main.tsx` содержимым `index.html`, страница не стартует вовсе — и единственная локальная проверка, где работает настоящий рантайм функций, перестаёт показывать интерфейс.

**Перед выкаткой в бой** — превью-деплой: `vercel deploy` даёт отдельный адрес и не трогает публичный. Часть поломок видна только там, потому что зависит от рантайма хостинга, а не от сборки. Стоит две минуты.

## Тесты

E2E на Cypress, прогон — на собранном бандле:

```bash
npm run build
npm run preview       # localhost:4173
npm run cypress:run   # в другом окне
```

Запросы к GitHub подменяются заглушкой (`cypress/support/github.ts`). Она отвечает по имени операции и курсору — по тем же признакам, что и настоящий прокси. Поэтому тестам не нужны ни токен, ни серверный рантайм: набор детерминирован и гоняется в CI на каждый пуш.

Так сделано не ради удобства. Прежний набор искал «tetris» и проверял, что в выдаче найдётся `react-tetris` — утверждение про ранжирование GitHub в конкретный день, а не про этот код; сейчас оно уже неверно. Теперь выдача генерируется, и падение теста означает, что изменилось приложение.

Если Cypress не стартует и пишет `bad option: --smoke-test` — дело не в бинарнике. Это `ELECTRON_RUN_AS_NODE=1` в окружении: Electron запускается как обычный Node и отвергает собственные флаги. Переменную выставляют дочерним процессам некоторые редакторы и обёртки; проверить `echo $ELECTRON_RUN_AS_NODE`, снять перед запуском.

## Команды

| Команда | Что делает |
|---|---|
| `npm run dev` | Дев-сервер |
| `npm run build` | Проверка типов и продакшен-сборка |
| `npm run lint` | ESLint |
| `npm run typecheck` | Только проверка типов |
| `npm run prepare:types` | Скачать схему и сгенерировать типы |
| `npm run codegen` | Сгенерировать типы из уже скачанной схемы |
| `npm run schema` | Только скачать схему |
| `npm run preview` | Локальный просмотр продакшен-сборки |
| `npm run cypress:open` | E2E-тесты в интерактивном режиме |
| `npm run cypress:run` | E2E-тесты в консоли |

Тестам нужен поднятый `npm run preview` — см. раздел «Тесты».
